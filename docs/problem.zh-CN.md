## 1. 用户是谁

### 用户 A：独居的香港长者

- 常常**同时服用好几种药**（多重用药），而且是由不同诊所的不同专科医生分别开的
- 药盒上的字**又小又全是术语**，或者说明书早就丢了
- 医生只当面讲一遍，**出了诊室就留不住**
- 典型的失败结果：**成分重复、漏服、不同专科的药搞混**

### 用户 B：外籍家庭佣工（主要来自菲律宾）

- **真正在做照护工作的是她们**：分药、提醒吃药、陪同复诊
- **她们看不懂中文** —— 标签、说明书、预约单对她们来说是一片空白
- 语言落差是双向的：**长者讲粤语，佣工听得懂英语或他加禄语，中间没有任何东西搭桥**
- 她需要的是**核对**，不是**诊断** —— 而她手上没有任何工具

> **产品的语音输出默认是英语**，服务于用户 B。
> **粤语（用户 A）是下一步。** 如果被问到，就照实说这个优先级，不要把它讲成已经交付了。

## 2. 真实的失败链条

```
医生当面讲一遍 -> 长者没有留住 -> 佣工看不懂中文说明书
   -> 药盒上的字太小 -> 她自己做判断 -> 加药 / 漏药 / 重复用药
```

**这不是效率问题，这是入院问题。**

---

## 3. 根因

> **核对几种药能不能一起吃，今天只有药师在做 —— 而这件事所需要的知识，在时间和空间上都被锁在药房里。**

它底下压着三个相互独立的事实：

| # | 事实 | 后果 |
|---|---|---|
| **1** | 核对用药安全需要的是**专业判断**，不只是查资料 | 长者和佣工**不具备这种判断** |
| **2** | 药师的**工作时间和地点**都有限 | **凌晨两点、周末、在家里**全都够不着 |
| **3** | 现有工具做的是**信息检索**，不是**核对** | 人真正卡住的那个地方，**从来没有被回答** |

**所以：问题不是没有人管。问题是管不到它真正重要的那一刻。**

---

## 4. 我们的立场

**我们不替代药师。我们提供的是一线响应。**

而一线响应的正确行为是**上报，不是猜。**

这句话直接对应题目原文：

> *"**A first-line response that escalates rather than guesses.**"*
>
> 中文：*"**一线响应应当上报，而不是猜测。**"*

## 5. 现有替代方案及其不足

| 现有方案 | 它做到了什么 | 它做不到什么 |
|---|---|---|
| **通用 AI 助手** | 你问什么它都能答 | 不认识香港本地的药名；不能离线运行；**而且会非常自信地答错** |
| **药盒里的说明书** | 官方、准确 | 就一张印满小字的纸，全是临床术语；**长者和佣工读不了** |
| **查药 App 与药典** | 你能查到这种药 | **给的是信息，不是判断**；需要联网；默认使用者识字 |
| **社区药剂师服务** | 真正的专业判断 | **要求本人到场，且只在服务时间内；够不到「现在、在家里」** |
| **我们的定位** | **在那一刻给出判断，并且清楚标出它不确定的地方** | — |
