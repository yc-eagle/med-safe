## 1. 失效模式

| # | 失效模式 | 什么情况下发生 | 严重度 | 我们的处理 |
|---|---|---|---|---|
| 1 | **药品识别错误** | 照片模糊、角度不好、光线不足、包装相似 | 高 | 重拍、换一张图，或输入注册编号。**照片与 OCR 只产生候选；由用户确认身份。** |
| 2 | **成分识别错误** | 复方制剂、保健品、非处方药包装 | 高 | 未映射成分**列为缺口**；身份仍须用户确认 |
| 3 | **规则覆盖不足** | 该配对不在 14 条规则之内 | 中 | 输出 **`no_rule_found`** —— 说明**未覆盖**，绝不输出 "no interaction found" |
| 4 | **中成药、中药与保健品未覆盖** | 中成药包装、中药材 | 中 | 在当前范围之外，**如实说明** |
| 5 | **语音识别错误** | 环境嘈杂、有口音 | **并非一律低** —— 听错的名字可能指向另一种药 | 屏幕同时显示文字；**绝不做纯语音**，而且用户仍要确认 |
| 6 | **给药途径不明确** | 途径未确认，或超出规则范围 | 中 | 输出 **`route_review_required`**；显示可能适用的警告，但不外推 |
| 7 | **过度简化** | 把一个复杂的风险压缩成一句话 | 中 | 措辞由 Lin MA 逐句审过 |
| 8 | **重复录入** | 同一产品被加入两次 | 低 | 输出 **`duplicate_input_requires_review`** |

**没有真实数据就不填任何错误率数字。** 发生率是刻意留空的。

## 2. 最重要的一条规则：怎么处理「我不知道」

> **L3（查不到数据）的正确输出是 "I cannot find information on these two medicines. Please consult a doctor." 它绝不能是 "no interaction found."**

**为什么这一条要单独拎出来讲：** 把「我们不知道」变成「没问题」，是这款产品唯一**不可原谅**的错误。前者只是没帮上忙。后者会造成伤害。

**这条必须在代码里强制**，不能只留成文档里的一个可选项。

## 3. 我们的模型不覆盖什么

**这一节与 [`decision-logic.md`](decision-logic.md) 中的「outside the model's capability」清单保持一致。** 两者要同步维护。

| 不覆盖 | 说明 |
|---|---|
| 剂量与用法 | 我们刻意**不给**任何剂量建议 |
| 疗程与给药间隔 | 未建模 |
| 患者本人的情况 | 年龄、肝肾功能、过敏史、妊娠与哺乳 —— **我们一概不知道** |
| 儿科方案 | 未覆盖 |
| 高阶相互作用 | 三种及以上药品一起作用不予评估；只评估两两配对 |
| 累积剂量 | 不予评估 |
| 中药材、中成药与保健品 | **未覆盖。** 在产品中如实说明 |
| 食物与药物的相互作用 | **未覆盖** |
| 用户今天已经吃过什么、什么时候吃的 | 我们不知道 |
| 召回监测 | 未覆盖 |
| 香港以外的药名 | 商品名各地不同 |

> **这些缺口无法靠下载更多模型权重来补上。** 它们需要可靠的数据、明确的范围与专业验证 —— 那是人的工作。

## 4. 我们刻意不做的四件事

> **MedSafe 是黑客松原型。它不是医疗器械，也不提供医疗建议。**

- 我们不做诊断。
- 我们不给剂量建议。
- 我们不建议停药、换药或调整用药。
- 我们不替代药师或医生。

**不确定的时候，正确的行为是把用户交给专业人士。**

## 5. 如果确实出错了

| 环节 | 安全兜底 |
|---|---|
| 识别置信度低 | 重拍、换一张图，或输入注册编号；它不猜 |
| 用户未确认身份 | 输出 `identity_confirmation_required`；完整核对不会继续 |
| 有未映射成分，或途径缺失 | 输出 `incomplete_check`；缺口保持可见 |
| 数据没有匹配上 | 输出 `no_rule_found` 并说明**未覆盖** |
| 途径未确认或超出范围 | 输出 `route_review_required`；作为需确认的提示显示，且不外推 |
| 同一产品被加入两次 | 输出 `duplicate_input_requires_review` |
| 输出措辞有歧义 | 由 Lin MA 逐句审过；演示前必须复核 |
| 系统完全不可用 | 界面直接写明：请咨询医生或药师 |
| 离线时的外部引用链接 | 链接无法访问；本地的摘要、日期与章节引用仍然保留 |

**每一个结果都附着两个标记，没有例外：** `clinicalSafety: not_assessed` 与 `coverageComplete: false`。**没有任何代码路径会给出安全结论。**

## 6. 怎么诚实汇报

**观察性研究与工程测试要分开报告。** 工程测试套件通过，只证明软件按规格运行。它**不是**临床有效性的证据，不是真实用户满意度的证据，也不是任何奖项级别的验证。

**没有真实数据就不写任何发生率。** 不知道的地方就留空，不要估算。

团队原来的框架 —— 错误分类、失败时怎么做、什么在范围之外 —— 保留在[团队规划存档](team-planning/README.md)。**这张表不代表已获专业批准的医学风险分级。** 14 条规则中获专业批准的是零条。
