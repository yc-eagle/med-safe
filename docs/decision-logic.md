# 多药核对的可追溯逻辑

[中文](decision-logic.md) | [English](decision-logic.en.md)

核心代码：`app/engine.js`。输入为 2 至 12 款互不重复的产品及用户确认状态、实际给药途径。单药资料查询是独立功能，不需要经过双药规则。

1. **身份**：完整 HK 注册号须存在于目录，用户逐项确认。OCR 的注册号／名称匹配只产生候选。模糊品牌无法唯一确定制剂；拒绝确认时不进入完整核对。
2. **成分**：从目录展开所有成分，NFKC／空白／大小写标准化后仅匹配显式别名。不依靠字符串包含或语言模型猜盐型等效。原始值和未映射值均保留。
3. **途径**：用户选择口服、舌下、外用等；未确认途径作为缺口。演示制剂名称导出的途径只是注明来源的提示，不能称已核对实物。
4. **逐对**：对 n 款产品枚举 n(n−1)/2 对，最多 66 对。每对同时列出原始目录同成分文本、命中规则、潜在规则、缺口和状态。
5. **证据**：两侧成分对应规则且两侧途径都在允许范围才输出适用警示；成分命中但途径未明／不符则列为待确认提示，不能外推。
6. **强度**：保留说明书禁忌、建议避免、风险增加、先咨询、重复成分等不同层级。风险提示不等于一律禁用。例如阿司匹林与氯吡格雷可能是医生有意安排的方案，不建议用户自行停药。
7. **完整性**：每对均给记录，无规则就注明未覆盖。即使一对命中，多药清单的其他缺口也不能消失。

目前每次结果固定包含 `clinicalSafety: not_assessed`、`coverageComplete: false`、`reviewStatus: pending_ella_review`；没有输出安全／绿色放行结论的分支。

## 结果含义

| 输出 | 含义 |
|---|---|
| identity_confirmation_required | 尚有产品未由用户核对 |
| incomplete_check | 未识别、途径缺失或有未映射成分 |
| alerts_found | 至少一条所选范围内有来源的规则命中 |
| no_rule_found | 当前规则库没有命中，不表示可合用 |
| route_review_required | 成分提示存在，但适用途径未满足 |
| duplicate_input_requires_review | 同一产品重复加入；先核实是否确为重复记录 |

`ingredientOverlaps` 只是目录成分文本相同的事实；不能冒充所有同类药风险。两个产品成分不同仍可能相互作用，同成分也须结合实际剂量和医嘱判断。

## 不在模型能力内

剂量、疗程、服用间隔、三药及以上高阶作用、肝肾调整、过敏匹配、孕哺／儿童方案、中药复方全面风险、食品交互和召回监测均未完成。这些缺口无法靠多下载模型权重自动消除，需要可靠数据、适用范围与专业验证。

## AI 输出验证

`app/verify.html` 先比对原始 AI 输出与独立确认的目录字段，再另行查规则。别名归一化、字段冲突、证据不足分别记录。规则查不到不是 AI 字段必然错，字段全对也不意味着医学判断已获验证。保留原始输出和核验过程；不制造失败案例或伪造平台记录。
