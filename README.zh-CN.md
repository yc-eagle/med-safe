# Ngon Sam · 藥安心 — 香港用药核对助手

[English](README.md) | [中文](README.zh-CN.md)

> **确认你手里拿的是什么，读出来源明确的警告，把没有答案的问题带去问药师。**

**关于名字。** Ngon Sam 是粤语「藥安心」的读音，意思是"对用药放心"，不是"用药安全"的承诺 —— 产品从不判定一个组合安全，界面上每一次结果都写着这一点。MedSafe 保留为内部项目代号，用于仓库路径与工程记录。

> 一个面向香港长者与照护者的 HacKU 2026 原型：拍下药盒，人工确认产品，查成分，逐对核对所选药品，用语音提问，最后带着一张给药师的问题卡离开。

## 对早期规划材料的更正

本仓库早期的规划文档对产品的描述，**与最终实现并不一致**。当它们与本 README、[`docs/decision-logic.md`](docs/decision-logic.md) 或程序本身冲突时，**以实现为准**。

| 早期规划的说法 | 实际实现 |
|---|---|
| 「先做英语语音输出，粤语排后面」 | **界面默认英文**，另设普通话与粤语切换（`?lang=en|cmn|yue`）。三者现在都可用。界面语言与语音可用性是两件事；切换语言只转换显示文字 —— 目录值、来源记录与临床规则不变。 |
| 「配伍禁忌就是这些药不能一起吃」 | **风险等级是分开的**：标签禁忌、标签建议避免、出血风险升高、需先咨询、成分重复。**风险升高的警告不是禁令。** 华法林加阿司匹林不得被升级为「所有病人都禁用」。 |
| 「发现风险时系统拒绝回答」 | 恰恰相反：**当有来源的规则匹配上时，它会显示警告**，并按正确的强度显示。它从不输出的是**「安全」结论**。没有匹配到规则是一种**覆盖**状态，绝不能被读回为药理上的安全。 |
| 「说明书从不提与其他药同服」 | **说明书是有相互作用章节的。** 真正的缺口是：需要看它的人看不懂它。不要声称「从不提」。 |
| 关于其他产品的概括 | 通用助手、药品工具与药师服务的具体能力，必须**逐个产品、逐项服务核实**。不得概括为「它们都不做这个」或「只有我们做」。 |

**另外注意：** 小浣熊（Raccoon Work）的评奖标准是 *Implementation & Completeness*（实现与完整度），对其中的 AI 生成输出做验证只是**其中一个组成部分**。不得改述为「AI 验证占 30%」。

## 运行

### 手机或桌面，在浏览器里

打开公开入口；不需要 GitHub 账号。用完整的香港注册编号或产品名搜索，确认药盒，选择实际给药途径，加入第二种或更多药品，逐对阅读结果及其来源。照片只帮助找到候选；**它不代表用户已经确认了身份**。单种药品可以单独查询，不必走逐对规则。

公开站点还通过了匿名 Chromium 对全部离线下载、离线重载与目录搜索的测试，另有 9 项规范 URL 跳转回归检查。真机手机测试仍未完成。

公开 URL 已由**匿名 Chromium 会话**验证：完成一次完整离线下载、一次离线重新打开，以及离线状态下的一次药品查询；同时新增了 **9 项站点跳转回归检查**。移动端离线升级通过了 16 项核心工程检查（53 个缓存资源，约 52.7 MiB，覆盖离线重新打开、查询、规则、OCR，以及离线时禁用语音）。**正式发布状态以页面上的离线下载入口为准。真机手机测试尚未完成。** 浏览器语音可能由浏览器厂商的服务器处理；这一点已披露，并且每次都会请求同意。**网页版粤语识别并非完全离线，不得如此描述。** 离线时仍可手动输入。只有当设备自带本地语音时才会使用本地语音。

### 桌面端，离线，不用模型

1. 在 GitHub 上选择 **Code -> Download ZIP** 并解压。
2. 打开 `app/index.html`。已下载的目录、材料、规则检查与问题卡在本地可用。
3. 如需浏览器 OCR 等完整网页功能，运行：

```sh
python3 -m http.server 8080 --bind 127.0.0.1 --directory app
```

然后打开 `http://127.0.0.1:8080`。识别资源随包提供，原始图像由浏览器处理；首次加载大资源可能较慢。相机权限取决于浏览器与安全上下文。**`file://` 回退不承诺相机或 OCR。** 外部来源链接离线时无法访问；本地的摘要、日期与章节仍然可用。

### Apple Silicon Mac：本地 OCR 与粤语识别

安装 Python 3，然后双击 `启动演示.command` 或运行 `python3 server.py`，并打开 `http://127.0.0.1:8765`。服务器只监听本机；**它不是队友手机可以连接的地址**。如果编译好的识别组件缺失，程序会尝试用已安装的 `swiftc` 编译 `native/ocr.swift`；没有开发者工具时，手动查询仍然可用。

本地粤语语音输入需联网运行一次：

```sh
python3 tools/install_voice.py
python3 server.py
```

安装器仅支持 Apple Silicon macOS。它会创建独立的 `.voice-runtime`，锁定依赖，并下载固定的 Qwen3-ASR 模型（约 0.7 GB）。**首次安装不是离线操作**；环境与模型就位后即可无连接运行。没有云端 API key。这个 MLX 粤语模型**不**为 Windows 或手机提供。完整步骤：[离线与资源](docs/offline.md)。

## 决策是如何做出的

核心代码：[`app/engine.js`](app/engine.js)。输入是 2 到 12 个不同产品，加上用户的确认状态与实际给药途径。

1. **身份。** 完整的香港注册编号必须存在于目录中，并由用户逐项确认。OCR 按编号或名称产生的匹配**只是候选**。模糊的品牌名无法唯一确定制剂；如果用户拒绝确认，完整核对不会继续。
2. **成分。** 所有成分从目录展开。经过 NFKC、空白与大小写归一化之后，**只匹配显式别名** —— 不做字符串包含，也不让语言模型猜测盐形式的等价关系。原始值与未映射值都会保留。
3. **途径。** 用户选择口服、舌下、外用等；未确认的途径按缺口处理。从演示制剂名称推导出的途径**只是有来源的提示**，未经实物包装核对。
4. **逐对。** 对于 *n* 个产品，枚举全部 *n(n−1)/2* 个配对，最多 66 个。每个配对同时列出原始目录成分、匹配到的规则、可能适用的规则、缺口与状态。
5. **证据。** 只有当两侧成分都对应到某条规则，**并且**两侧途径都落在许可范围内时，警告才成立。如果成分匹配但途径未确认或超出范围，它会被列为需确认的提示，不得外推。
6. **强度。** 标签禁忌、标签建议避免、风险升高、需先咨询与成分重复保持在**不同等级**。**风险警告不是一概禁止。** 例如阿司匹林与氯吡格雷可能是刻意的联合方案；不会建议用户自行停用。
7. **完整性。** 每一个配对都有记录；如果没有规则适用，就标记为未覆盖。即使某一个配对匹配上了，多药清单中其余的缺口也不会消失。

### 输出可能意味着什么

| 输出 | 含义 |
|---|---|
| `identity_confirmation_required` | 至少有一个产品尚未由用户确认 |
| `incomplete_check` | 有未识别产品、缺失途径或未映射成分 |
| `alerts_found` | 在所选范围内至少有一条有来源的规则匹配 |
| `no_rule_found` | 当前规则库中没有匹配 —— **这不代表该组合是安全的** |
| `route_review_required` | 存在成分提示，但适用途径的条件未被满足 |
| `duplicate_input_requires_review` | 同一产品被加入两次；先确认它是否真的是重复 |

`ingredientOverlaps` 只记录目录中的成分文本相同。不得把它呈现为整个药物类别的风险。**成分不同的两种产品仍可能相互作用，成分相同也仍需结合实际剂量与处方来判断。**

### 模型能力之外

剂量、疗程、给药间隔、三种及以上药品的高阶相互作用、肝肾功能调整、过敏匹配、妊娠、哺乳与儿科方案、多味中药复方的综合风险、食物相互作用，以及召回监测都**没有**覆盖。这些缺口无法靠下载更多模型权重来补上；它们需要可靠的数据、明确的范围与专业验证。

### 验证 AI 输出

[`app/verify.html`](app/verify.html) 先把原始 AI 输出与独立确认过的目录字段对比，然后再单独检查规则。别名归一化、字段冲突与证据不足都分别记录。**没有找到某条规则不代表 AI 字段一定错；所有字段都正确也不代表医学判断已经过验证。** 原始输出与验证过程都会保留；不制造失败案例，也不伪造平台记录。

## 可用性与隐私

繁体中文与英文、大字模式、重拍与选择文件、识别后更正、显式列出缺口、给药师的问题卡，以及当用户自己的处方与包装冲突时的提示，都是为了减少误读与出错。拒绝相机或麦克风权限仍可手动输入。**照片或录音从来不是必需的。**

在浏览器版本中，照片在设备上识别。在 Mac 版本中，照片与录音只发送到同一台电脑上的本地服务，临时文件随请求删除。**浏览器语音可能把录音发送给浏览器厂商**，这一点单独披露。见[什么会离开设备](docs/data-handling.zh-CN.md)。

**工程可用性测试不等于与真实长者的研究；真实场景观察尚未完成。**

## 目录结构

```text
app/                   浏览器产品、识别资源、AI 字段验证页
native/                macOS Vision 与本地语音工作进程
server.py              仅本机
data/                  当前完整清单、成分材料、患者措辞、词表
data-pack/data/        注册目录、规则、别名、SQLite、来源元数据
data-pack/raw/         有许可的开放目录 XML / XSD
docs/                  场景、决策、数据处理、验证与提交说明
docs/rules/review.csv  医学审阅表；批准列无法自动填写
tests/, qa/            工程检查与结果；它们不能替代临床验证
```

新代码位于 `app/`、`native/` 与 `server.py` —— **不在**计划中的 `src/`。

规则变更时，要同时更新来源、适用途径、证据等级、日期与专业审阅表，然后运行 `python3 tools/build_data.py`。当前事实由本 README、`docs/`、`data/data_inventory.json` 与程序实际行为决定。**更早的交接材料不代表当前完成状态。**

核心规则测试：`node tests/engine.test.cjs`、`node tests/patient.test.cjs`、`node tests/validator.test.cjs`、`node tests/product-features.test.cjs`。浏览器与本地 API 测试需要各自的环境；见[技术报告](TECHNICAL_REPORT.md)。
